## Порядок и параллельность

Рекомендуемая последовательность: **PRD-01 → PRD-02 → PRD-05** (каждый следующий
потребляет интерфейс предыдущего). PRD-03, PRD-04, PRD-06 — в любой момент с учётом:

- **Нельзя параллелить**: PRD-01 ∥ PRD-03 ∥ PRD-04 (все трогают `app/models.py`).
- **Можно параллелить**: PRD-06 с чем угодно; PRD-05 с PRD-03/PRD-04;
  PRD-02 с PRD-03/PRD-04/PRD-06.

## Общие требования ко всем PRD

1. **Поведение не меняется.** Все PRD — рефакторинги. HTTP-статусы, формы JSON-ответов,
   содержимое БД и логика бота остаются прежними, если PRD явно не говорит иное.
2. **Существующие тесты проходят.** Разрешено обновлять только import-пути в тестах;
   assert'ы менять нельзя. Прогон: `python -m pytest` (см. «Тестовое окружение» ниже).
3. **Стиль кода** — как в репозитории: async/await, параметризованные SQL-запросы,
   logging, русские докстринги допустимы. Файлы < 800 строк, функции < 50 строк,
   без мутации входных структур (создавать новые объекты).
4. **Никаких новых зависимостей** без явного указания в PRD.
5. **Коммиты** — conventional commits (`refactor:`, `feat:`, `test:`).

## Тестовое окружение

Integration-тесты ходят в одноразовый Postgres (`tests/conftest.py:15`):

```bash
docker run -d --name clio-test-pg -p 55432:5432 \
  -e POSTGRES_USER=test -e POSTGRES_PASSWORD=test \
  -e POSTGRES_DB=telegram_bot_test postgres:16
python -m pytest
```

Переопределение: переменная окружения `TEST_DATABASE_URL`.

## Доменный словарь (используется в PRD)

- **spam-пометка / flag** — строка в `spam_users`; ставится при «полном бессрочном муте»
  антиспам-ботом, снимается при размуте (`app/bot/spam_detection.py`).
- **дайджест / аналитические выборки** — запросы для саммари/стратегии/аналитики;
  **обязаны** исключать помеченных спамеров.
- **сырая вьюха админки** — просмотр сообщений в админке; **обязана НЕ** фильтровать
  спамеров (скоуп зафиксирован в `tests/test_spam_filtering.py:70`).
- **саммари** — отчёт за 24 часа; **стратегия** — контент-рекомендации за неделю/месяц;
  **аналитика** — счётчики по дням + AI-комментарий.
- **vibecoder-чат** — специальный чат (`Config.vibecoder_chat_id`), для которого
  работает авто-отклонение join-заявок «свежих» аккаунтов.
